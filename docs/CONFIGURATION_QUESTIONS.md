# 100 Configuration Questions for Shelter Management System

## System Setup (Questions 1-20)

1. What is the official name of your shelter organization?
2. What is the primary contact email address for the system?
3. What is the emergency hotline phone number?
4. What is the physical address of your main location?
5. What are your standard operating hours?
6. How many staff members will be using the system?
7. How many volunteers do you expect to register?
8. What is your expected number of active clients?
9. Should the system enable public access to the landing page?
10. What timezone should the system use for all timestamps?
11. Do you want to enable automatic email notifications?
12. Do you want to enable SMS notifications?
13. What language(s) should the system support?
14. What is your preferred date format (MM/DD/YYYY or DD/MM/YYYY)?
15. What is your organization's logo URL or file path?
16. What are your organization's primary brand colors?
17. Should maintenance mode be available for scheduled downtime?
18. What is the maximum file upload size for documents (in MB)?
19. How long should user sessions remain active (in minutes)?
20. Should the system log all user activities for auditing?

## Client Management (Questions 21-35)

21. What information is required during client registration?
22. Should clients be able to self-register or only staff can add them?
23. How often should intake assessments be updated?
24. What risk levels should trigger immediate notification to staff?
25. Should clients have access to their own assessment results?
26. What types of client documents should be tracked?
27. Should document expiry dates trigger automatic reminders?
28. How long should client data be retained after case closure?
29. Should clients be able to update their own profile information?
30. What privacy level should client information have (staff-only vs. visible to volunteers)?
31. Should the system track client's family members and dependents?
32. What languages do your clients primarily speak?
33. Should clients be able to communicate with each other?
34. How should emergency contacts be managed and verified?
35. Should clients receive automatic appointment reminders?

37. Should substance use be categorized by type (alcohol, drugs, both)?
38. How detailed should employment history tracking be?
39. Should the system track education and certification completion?
40. What legal issue categories should be tracked?
41. Should assessments include mental health screening questions?
42. How many priority levels should be available for client needs?
43. Should assessments automatically calculate risk scores?
44. What factors should contribute to risk score calculation?
45. Should reassessments be scheduled automatically?
46. How frequently should high-risk clients be reassessed?
47. Should assessment data feed into automatic service matching?
48. What threshold scores should trigger case manager alerts?
49. Should clients be able to request reassessment?
50. How should assessment data be shared with service providers?

## Service Provider Integration (Questions 51-65)

51. What types of service providers will you work with?
52. Should service providers have direct system access?
53. How should provider availability be tracked and updated?
54. Should the system automatically match clients to available services?
55. What information should be shared with service providers?
56. Should provider referrals require approval before submission?
57. How should you track referral outcomes and success rates?
58. Should providers be able to update client status directly?
59. What notification triggers should alert providers of new referrals?
60. Should the system track wait times for different services?
61. How should provider capacity limits be managed?
62. Should emergency services have priority routing?
63. What communication methods should be available for providers?
64. Should provider performance metrics be tracked?
65. How should you handle services that require specific documentation?

69. How frequently should case managers meet with clients?
70. Should the system track case notes and meeting summaries?
71. What goal-setting framework should be implemented?

73. Should clients be able to view their case notes?
74. What types of interventions should be tracked?
75. Should the system support crisis intervention protocols?
76. How should case escalation procedures work?
77. Should successful outcomes trigger celebration notifications?
78. What metrics define "success" for your organization?
79. How long should completed cases remain accessible?
80. Should case managers be able to transfer clients to colleagues?
